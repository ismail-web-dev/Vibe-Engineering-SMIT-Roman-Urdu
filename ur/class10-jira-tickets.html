Class 10 · 10.3

Planning V1: Jira tickets likhna

Product ko bilkul real team ki tarah plan karein — PL-4 se PL-7 tak wazeh tickets ka backlog, jo stakeholder ki aawaz mein likha gaya ho, aur phir ek ek karke apne sab se qabil teammate ko sonpa gaya ho: Claude Code.

🎯 Goal: shippable backlog tayar karna⏱ Read: 12 min🧪 Type: planning

Bunyad rakh di gayi hai. Ab hum asal product ko bilkul ek professional team ki tarah plan karte hain — tickets likh kar. Tasawwur karein ke aap ka engineering lead, product manager, business sponsor, ya clients khud Jira mein yeh tickets bana rahe hon. Aam taur par yeh ek poori team mein taqseem hotay hain; magar hum yeh saare ke saare apne ek intehai qabil teammate ko assign karne ja rahe hain: Claude Code.

01Prototype se real V1 tak

Jira mein wapis ja kar thori safai karein: woh shuruati “simple website” card (PL-1) apna maqsad poora kar chuka hai, lehaza usey delete kar dein. NDA prototype (PL-3) ne concept sabit kar diya tha. Ab hum mukammal V1 ke safar ko chand wazeh tickets mein baant'te hain, jin mein se har ticket ek aisa qabil-e-zikr marhala (meaningful step) hai jise har stakeholder asaani se samajh sake.

02Chaar V1 tickets

Yeh raha plan — jaan boojh kar business aur technical aawazon ke imtizaj ke sath likha gaya hai, kyunki real life mein yeh mukhtalif logon ki taraf se aatay hain:

Ticket Title Yeh kya mangta hai
PL-4 Build foundation of V1 Prototype ko ek proper technical foundation mein upgrade karein — frontend, backend aur start/stop scripts ke sath ek temporary database — abhi koi naye product features add kiye baghair. (Yeh technical-lead ka ticket hai.)
PL-5 Add AI chat (still just NDA) Product ke interact karne ka tareeqa tabdeel karein: sawalat ki lambi series ke bajaye, AI ke sath ek free-form chat jo document ke baare mein poochhe, zaroori fields dhoonde, aur user ke jawabat se unhein fill kare.
PL-6 All document types Tamam document types ko support karne ke liye expand karein jin ke templates mojood hain. Agar user koi aisa document maange jo supported na ho, toh usey wazahat karein ke hum yeh nahi bana sakte — magar qareebi tareen mutabadil offer karein.
PL-7 Multiple users & final polish Proper sign-up / sign-in; pehle se generate kiye gaye documents ko save aur dobara open karna; database restart hone par reset ho sakta hai; har screen ko professional SaaS jaisa chamkayein; aur ek “draft, subject to legal review” disclaimer shamil karein.
Jaan boojh kar stakeholder ke lehjay mein likhein (Write in the stakeholder's voice)

Ghaur karein ke PL-5 mein Cerebras ya structured outputs ka koi zikr nahi hai — yeh jaan boojh kar kiya gaya hai. Tickets mein insani alfaaz mein bataya jata hai ke kya banana hai (what); jabke kaise karna hai (how) woh CLAUDE.md, skill, aur Claude ke apne faislay se tay hota hai. Thori gunjaish chhorna ek behtareen feature hai, koi kotahi nahi.

03Fake login se shuru karein

PL-4 ke liye hum ne ek baat wazeh tor par likhi hai: filhal sirf ek fake login screen banayein, koi real authentication nahi — bas user ko platform ke dashboard par le aayein. Hum shuru mein hi auth ka bojh nahi daalna chahte; real sign-up/sign-in PL-7 mein aayega. Mushkil hisson ko aage ke liye schedule karne se har ticket chhota aur ba-asaani ship hone ke qabil rehta hai.

04Product Owner ki tarah sochein

Do

✅ Detail hamesha Description mein likhein

Ticket ki asal requirements hamesha Description field mein likhein — kyunke Claude wahi se parhta hai. (Aksar log ghalti se Comments box mein likh dete hain!)

Do

✅ Business-speak bilkul perfect hai

“User ke sath interact karne ka tareeqa badlein” ek behtareen ticket description hai. Aap ko code ki zaban bolne ki koi zaroorat nahi — code likhna toh model ka kaam hai.

Board par PL-4 se PL-7 mojood hone ke sath, hamara Kanban ek asli product backlog jaisa lagta hai. Kisi company mein yeh mukhtalif engineers ko distribute hote. Magar hum yeh poora kaam ek ek karke Claude Code ko sonpne ja rahe hain.

05Claude ko assign karein — aur skill check karein

Terminal mein claude chalayein aur /context command run karein. Code likhwane se pehle do ahem cheezein check karein:

Aap ki skill recognise ho chuki haicheck

Aap ko Cerebras inference ek project skill ke tor par nazar aani chahiye — jo is baat ka saboot hai ke .claude/skills/cerebras folder bilkul theek detect ho gaya hai.

Plugins aur MCP servers mojood haincheck

FeatureDev, aur aap ke Atlassian aur GitHub MCP tools active hon. Note karein ke yeh context window ka ek munasib hissa lete hain — yeh MCP trade-off ka amli saboot hai.

Atlassian ko re-authenticate kareinritual

Aap ko routine pata hai: /mcp → Atlassian → Re-authenticate → Approve → Accept. Agar yeh chhor diya toh pehla Jira read hi hang ho jaye ga.

✓ Aham Nakaat (Key Takeaways)

  • V1 ko chand wazeh tickets (PL-4 se PL-7) ke andar plan karein, har ticket ek aisa step ho jise business stakeholder pehchan sake.
  • Tickets ko insani/business zaban mein likhein; kaise karna hai yeh CLAUDE.md, skill aur Claude ki technical samajh par chhor dein.
  • Mushkil cheezon ko tarteeb dein: pehle fake login (PL-4), real auth aakhir mein (PL-7).
  • Requirements ko ticket ke Description field mein likhein, Comments mein nahi — kyunke Claude Description parhta hai.
  • Build shuru karne se pehle confirm karein ke aap ki project skill /context mein show ho rahi hai, aur Atlassian MCP ko re-authenticate kar lein.
