Features build karna: Pehle foundation, phir AI chat

PL-4 aur PL-5 ko Jira se merged code tak le kar chalein. Architecture stage par inquisitive manager banna seekhein, tickets ke darmiyan context ko saaf rakhna, aur streaming ke baare mein ek real design debate jeetna.

🎯 Goal: PL-4 aur PL-5 ship karna⏱ Read: 16 min🧪 Type: live build

Ab waqt hai practical build karne ka. FeatureDev rails par charh chuka hai aur sab kuch connect ho chuka hai, ab hum apne pehle do product tickets — PL-4 (technical foundation) aur PL-5 (AI chat) — Jira se utha kar seedha main branch mein merged code tak le jayen ge. Yeh page aap ko yeh bhi sikhaye ga ke architecture stage par ek inquisitive manager (sawalat poochne wala manager) kaise banna hai, aur tickets ke darmiyan context window ko saaf suthra kaise rakhna hai.

01PL-4: foundation build karein

Sirf ek single command se kaam shuru hota hai:

claude
feature-dev:feature-dev implement Jira ticket PL-4 and make a PR.

Yeh Jira se PL-4 ticket uthata hai aur is martaba process ko mazeed baqaidagi se follow karte hue nihayat zahanat bharay clarifying questions poochta hai — kya authentication poori tarah functional honi chahiye ya filhal placeholder? (hum ne kaha: placeholder), kya NDA form sirf client-side par rahe ya backend database mein save ho? (client-side). Phir yeh architecture-design stage par aa kar ruk jata hai aur poochta hai: “kya aage barhne ke liye yeh approach theek lag rahi hai?”

Aisi hi saaf suthri, containerised structure FeatureDev propose karta hai — aur build karne se pehle aapse approval maangta hai.
Inquisitive manager banein

Yeh review step aap ke ikhtiyar (power) ka lamha hai — chahe aap bohot zyada technical na bhi hon. Aap “chat about this” chun kar sawalat (probe) kar sakte hain: SQLite kyun? Single container hi kyun? Wohi sawalat poochein jo ek qabil manager trade-offs ko samajhne ke liye poochta hai. Is process ke tehat guide hone ki wajah se, Claude un ghaltiyon se bach jata hai jo us ne pehle ghair-tarteeb shuda projects mein ki theen (jaise ek hi bari monolithic main.py bana dena). Jab structure samajh mein aa jaye — toh approve karein aur usey code likhne dein.

02Khud test karein, phir merge karein

Agent report karta hai ke kaam ho gaya — tamam 76 tests pass ho gaye, API endpoints ban gaye, aur PR raise ho gayi. Trust karein, magar verify zaroor karein. Terminal mein start script chalayein aur browser mein kholein:

terminal
scripts/start-mac.sh      # builds & starts the container
# open http://localhost:8000 — "New York" type karein, live preview dekhein,
# PDF download karein — sab kuch chal raha hai, ab real infrastructure par

Yeh naye backend par bilkul theek chal raha hai, live preview update ho raha hai, aur PDF bhi download ho rahi hai. Phir agent ko kahein: “please merge the PR locally, push to main, and switch branch to main.” Bunyad kaamyabi se ship ho gayi!

03Tickets ke darmiyan context hygiene

Agli bari ticket shuru karne se pehle notice karein ke aap ka context window taqreeban full ho chuka hai. Yahan ek professional aadat apnayein: Claude se bolein ke woh apni progress CLAUDE.md mein likh de, aur phir context ko reset karein.

CLAUDE.md update karein1 min

“Add concise details to the end of CLAUDE.md on what has been implemented, and change anything that is no longer accurate.” Ab aap ke project ki ahem state ek permanent file mein mehfooz ho gayi hai, sirf temporary chat conversation mein nahi.

Phir /clear karein10 sec

/clear chala kar guzishta conversation ko saaf karein aur agla ticket bilkul taaza dam shuru karein. Aap ki CLAUDE.md (ek chhoti si memory file, taqreeban 1.8k tokens) pehle hi automatically load ho jaye gi — toh koi bhi zaroori baat bholay gi nahi!

Aakhir hum ise auto-compact par kyun nahi chhor dete?

Log compact se be-wajah nahi dartay: jab Claude bhari hui context window ko daba kar chhota (squash) karta hai, toh woh baaz ahem cheezon ko apni marzi se bhool (selectively forget) sakta hai — yahan tak ke CLAUDE.md ke hissay bhi — jis ke baad performance kharab ho sakti hai. Progress ko file mein save karna aur ek saaf suthra /clear run karna compact ke juye (gamble) par bharosa karne se kahin zyada safe hai.

04PL-5: AI chat add karein

Atlassian ko dobara re-authenticate karein (yahan hang hone ka matlab sirf auth reminder hai), phir bolein: feature-dev:feature-dev implement Jira ticket PL-5 and make a PR. Is ke clarifying questions la-jawab hain — bilkul wohi jo aap ek asli product owner se poochte:

Yeh poochta hai… Hum chunty hain
Chat UI form ko replace kare ya dono sath rahein? Form ko mukammal Replace karein
Document preview: live update ho ya submit par? Live updates
Conversation kaise shuru honi chahiye? AI greet kare aur pehla sawal pooche
Jab tamam fields fill ho jayen? Confirm kare aur download ka option dikhaye

Architecture stage par yeh parallel mein **teen specialized agents** launch karta hai — ek *minimal*, ek *clean*, aur ek *pragmatic* design — aur sab ke trade-offs samnay rakhta hai. Yeh woh jagah hai jahan aap ki product samajh kaam aati hai:

“Mujhe simple backend chahiye, magar sirf ek LLM call aur koi streaming nahi — Cerebras itna fast hai ke streaming ki zaroorat hi nahi parti. Ek structured-output call jo response aur extracted fields dono ek sath return kare woh kahin zyada clean aur stable hai.”

Khul kar behas karein (Have the debate out loud)

“chat about this” chunne se yeh review ek asli engineering guftagu ban jata hai. Claude ne streaming ke haq mein munasib daleel di; aap ne usay aisi haqeeqat se aagah kiya jo usey pehle se pata nahi thi (ke Cerebras kitna shocking fast hai), aur woh maan gaya ke simple design hi behtareen hai. Yahi aapas ki behas — ek genuine engineering debate — aala tareen nataij deti hai. Is ke baad woh jaa kar implementation shuru karta hai.

✓ Aham Nakaat (Key Takeaways)

  • Ticket ko sirf ek line se shuru karein: feature-dev:feature-dev implement Jira ticket PL-4 and make a PR.
  • Architecture-review stage par inquisitive manager banein — approve karne se pehle trade-offs ko achhi tarah parakh lein.
  • Merge karne se pehle khud apne hathon se test karein, chahe agent claim kare ke saare tests pass hain.
  • Tickets ke darmiyan: progress ko CLAUDE.md mein likhein, phir /clear karein — auto-compact par andha aitabar karne se kahin behtar hai jo baaz auqat ahem cheezein bhool jata hai.
  • PL-5 ke liye ek live design debate (ek structured call, koi streaming nahi kyunke Cerebras intehai tez hai) ne sab se clean architecture paida ki.
