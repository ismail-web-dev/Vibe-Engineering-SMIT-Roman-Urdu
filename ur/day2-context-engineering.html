Class 3 · 3.2

Context engineering & agents.md

Model ka output mukammal taur par uske input par depend karta hai. Is input ko bilkul durust rakhna — yaani context ko sanwarna — hi poori engineering hai. Yahan dekhein isme kya kuch shamil hota hai, kam information aksar zyada behtar kyun hoti hai, aur agents.md file aapke agent ko seedhi simt mein kaise chalati hai.

🎛 Maqsad: Control karein ke model kya dekh raha hai⏱ Parhein: 11 min

01Context asal mein sab kuch kyun hai

Kyunki LLM stateless hota hai, iska har ek output sirf aur sirf us waqt mile input par munhasir hota hai. Is poore input packet ko context kaha jata hai — yaani woh tamam maloomat jo model ko apna kaam karne ke liye di gayi hain. Chunache output seedha input ka natija hai, context ko theek karna hi dar-asal poora hunar hai.

Pehle hum isey prompt engineering kehte the. Magar ab yeh barh kar context engineering ban chuka hai — kyunki ab sirf sawal ya prompt nahi, balke model ke ird-gird ka poora mahool ahem hai: use kon se tools diye gaye hain, konsi memory aur project files shamil hain. Model ko bilkul sahi maloomat faraham karne ka yeh poora nizam context engineering kehlata hai.

02Context ki anatomy (Tarkeeb)

Us aik single input ke andar bohot saari cheezein teh-dar-teh (layers mein) jaati hain. Aam taur par inki tarteeb yeh hoti hai:

Kyunki model stateless hai, poora stack har call par dobara bheja jata hai.
  • System prompt — sab se bunyadi hidayat: model ka role kya hai, uska lehja (tone) kaisa ho, aur uska asal maqsad kya hai. Yeh hamesha shuru mein rehta hai.
  • Tool descriptions — un actions ka menu jo model chala sakta hai. Jitne zyada tools honge, utni zyada context space kharch hogi. (Baaz log isey system prompt ka hissa hi shumar karte hain, yeh sirf naam ka farq hai.)
  • Memory — aisi ahem maloomat jo aap mukhtalif conversations ke darmiyan hamesha mehfooz rakhna chahte hain.
  • agents.md — project ke maqasid, standards aur coding usool.
  • The conversation so far (Ab tak ki guftagu) — yeh sab se bara hissa hota hai. Pichla har message, model ki reasoning, uska likha gaya code, aur run hone wale tools ka output. Yeh sab isliye bheja jata hai taake agla token poori pichli tareekh se hum-aahang rahe.

03Context window (aur kam space zyada kyun behtar hai)

Ek call mein kitne tokens aa sakte hain iski ek qat'ee limit hoti hai — jise context window kehte hain. Is se tajawuz karne par API call fail ho jaati hai.

ModelContext window size
OpenAI GPT-5.2400,000 tokens
Claude Sonnet 4.5 / Opus 4.5200,000 tokens
Gemini 3 (Antigravity)1,000,000 tokens
Ahem aur hairat-angez baat (Counter-intuitive)

Sirf limit ka khatam ho jana hi wahid masla nahi hai. Limit se bohot pehle bhi, context ko be-tahasha bhar dene se model ki quality girne lagti hai — speed par nahi, balke uski samajh, durusti aur rabt (coherence) par farq parta hai. Conversation ke shuru mein jab context saaf suthra aur khali hota hai, to model sab se behtareen nataij deta hai. Less is more (kam behtar hai).

Compacting — summary banana

Jab context window bharne lagti hai, to fail hone ke bajaye Claude Code jaise tools compacting ka sahara lete hain: woh ab tak ki guftagu ka khulasa (summary) bana kar pichle messages ko replace kar dete hain taake nayi jagah ban sake. Yeh bohot faida-mand hai — magar pehle log is se darta thay kyunki aap model par bharosa karte hain ke woh khud faisla kare kya zaroori tha. Kabhi kabhar woh kisi ahem baat ko chhorh deta tha aur agent "bhool" jata tha.

2026 ki tajweez: compactor par bharosa karein

Pehle developers ki aadat thi ke agent ko rok kar khud hath se agents.md ko rewrite karte aur scratch se session shuru karte. Magar ab compacting waqai intehayi behtareen aur qabil-e-aitmad ho chuki hai. Shuru mein is par bharosa karein — yeh aam taur par zaroori hissay mehfooz rakhti hai. Manual reset sirf tab karein jab aapko sakht control darkar ho.

04agents.md — agent ko guide karne wali file

agents.md file aapke agent ko project aur uske usoolon ke baare mein brief karti hai. Yeh ek markdown file (.md) hoti hai — ek aasan, insano ke parhne ke qabil format jise LLMs intehayi pasand karte hain kyunki unhone aisi lakhoon files parhi aur likhi hoti hain.

Markdown 20 seconds mein

Sadah text aur thori si formatting

# Heading H1 heading banata hai, ## Sub H2, - se bullet banta hai, aur numbers se list. Code ko backticks mein wrap karein. Bas yahi kafi hai.

Mukhtalif Naam

Aik hi concept, mukhtalif filenames

Cursor / Codex / Copilot agents.md use karte hain. Claude Code claude.md use karta hai. Antigravity gemini.md use karta hai. Sab ka maqsad ek hi hai.

Hierarchy (Darja-bandi)

Project root mein mojood agents.md hamesha context mein load hoti hai. Iske ilawa aap kisi bhi subdirectory ke andar bhi ek alag file rakh sakte hain — aur woh sirf tab load hoti hai jab agent us makhsoos folder ki files par kaam kar raha hota hai. Andar wali file ke usool bahar wali root file ke usoolon par ghalib (override) aa jaate hain, jis se aap gehrai mein mazeed specific ho sakte hain.

Subdirectory files ke baare mein ahem nuqta

Root file hamesha context mein rehti hai. Subdirectory files sirf tab shamil hoti hain jab agent us makhsoos folder ko chhoota hai. Yeh hai asal wazahat ke “agents.md hamesha load hoti hai” ka kya matlab hai.

Ek achi agents.md mein kya hona chahiye

Isey ek professional prompt ki tarah likhein: mukhtasar, wazeh, do-tok, bila-shuba, aur har lafz mein maximum maqsad — kyunki yeh aapki qeemti context space leti hai.

  • Overall project ke ahdaaf aur kamyabi ka meyaar (success criteria) — behtar hai ke ek checklist ho jise agent tick kar sake.
  • Deegar ahem documents ke links jinhe agent zaroorat parne par parh sake.
  • Wazeh coding standards, jo khas taur par maazi ki ghaltiyon ko theek karne ke liye banaye gaye hon.
agents.md · coding-standards misal
## Coding standards
- Simpler is better. Never over-engineer; always simplify.
- Comments only when necessary. Be concise.
- Keep READMEs short. IMPORTANT: no emojis, ever.
- Avoid over-defensive programming; handle exceptions only when needed.
- Use latest, idiomatic library versions as of today.
Tajurbe se sabit shuda do tips

Capital haroof mein IMPORTANT likhna waqai model ki tawajjah kheenchne mein madad karta hai. Aur manfi ke bajaye musbat (positive) hidayat dein — LLMs aksar yeh yaad rakhne mein ghalti kar jaate hain ke kya nahi karna, isliye unhe wazeh batayein ke kya karna hai. Nihayat zaroori baton ko thoda repeat karna bhi theek hai.

Do mukhtalif falsafay (Two schools of thought)

2025 ka andaz-e-fikr

agents.md par khoob mehnat

Kamyabi ek nihayat sharp aur tarashi hui agents.md se milti thi: root aur subdirectories files, supporting plans aur success criteria. Isko musalsal tarashna, reset karna aur fresh start lena. Mehnat thi, magar isne bara farq dala.

2026 ka andaz-e-fikr

Khula chhorh do (Let it hang out)

Bagorein dheeli kar dein. Sirf aakhri goal par focus karein, skills, loops, sub-agents aur swarms ka istemal karein, aur agent ko khud ghaltiyan theek karne dein. Pichle saal ke muqablay mein ek wazeh tabdeeli.

Instructor ka apna imandarana nuqta-e-nazar: sanjeeda aur baray projects ke liye hum abhi bhi 2025 ke mindset (context engineering aur mazboot agents.md) ko tarjeeh dete hain — kyunki context par ki gayi mehnat ka behtareen phal milta hai — jabke chotay ya fun projects ko khula chhorh dena hi munasib hai. Yeh project ki noiyat par depend karta hai, jaisa ke aglay page par hum tafseel se dekhein ge. 2026 ke dauran tawaqqo hai ke yeh tawazun mazeed "let it go" ki taraf jhuk jaye ga.

✓ Aham Nakaat (Key Takeaways)

  • Output sirf input par munhasir hota hai, is liye context engineering hi poora khel hai.
  • Context teh-dar-teh banta hai: system prompt, tools, memory, agents.md, aur poori guftagu — jo har call par dobara bheji jaati hai.
  • Less is more: hard limit se bohot pehle hi, context bharne se model ki zehni salahiyat mutasir hoti hai.
  • Modern compacting par apne shukook se barh kar bharosa karein.
  • agents.md agent ko steer karti hai: mukhtasar, musbat, zaroori alfaaz capital mein, aur darja-band (hierarchical).
